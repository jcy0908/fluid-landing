01 / Question

문제 설정

Project brief

‘부드러움’을 프레임 수가 아닌
통제권의 연속성으로 다시 묻다.

빠른 애니메이션도 사용자가 방향을 바꾸는 순간 입력을 잃으면 끊겨 보입니다. 이 작업은 정해진 시퀀스를 더 매끈하게 만드는 대신, 진행 중인 모션을 언제든 다시 잡고 다른 목표로 보낼 수 있는 상태 시스템을 설계합니다.

Question
새 입력이 들어온 바로 그 프레임에 기존 움직임을 넘겨줄 수 있는가?
Reframe
시간 기반 재생 문제를 현재값·속도·목표·의도의 상태 문제로 바꿨다.
Constraint
HTML, CSS, JavaScript만 사용. 외부 모션 라이브러리 없음.
Output
가로 트랙, 중단 가능한 시트, 스프링 계기판, 실패 조건 기록.

출발점은 Apple의 Designing Fluid Interfaces (WWDC18)입니다. 원리를 웹 입력 환경에서 다시 구현한 개인 스터디이며 Apple의 제품 코드나 소속 프로젝트가 아닙니다.

Approach 중간 입력 속도 인계 Decision

CSS transition과 Web Animations도 중단·반전할 수 있습니다. 이 프로젝트가 스프링을 택한 이유는 “다른 방법은 불가능해서”가 아니라 위치와 속도, 사용자의 의도를 같은 모델에서 직접 관찰하고 넘겨주기 위해서입니다.

05 / Model

구현 규칙

Operating rules

감각적인 움직임을
검사 가능한 규칙으로 바꿨다.

  1. 01

    입력과 확정을 분리한다

    pointerdown에는 즉각 피드백을 주고, click 또는 pointerup에서 행동을 확정한다.

    feedback ≠ action
  2. 02

    지금 보이는 값에서 시작한다

    새 모션은 목표값이 아닌 현재 position과 velocity를 이어받는다.

    next ← current
  3. 03

    목표와 의도를 분리한다

    닫힘 목표와 사용자의 닫기 의도를 별도 상태로 둬 재그랩 뒤 오판을 막는다.

    target ≠ intent
  4. 04

    속도는 유효한 동안만 쓴다

    최근 100ms 이력만 남기고, 멈춰 있던 시간이 길면 속도를 0으로 본다.

    v = Δx / Δt
  5. 05

    탄성에는 근거가 필요하다

    충분한 던지기 속도가 있을 때만 낮은 감쇠를 허용하고 나머지는 임계 감쇠한다.

    |v| > 240

10px 미만 재그랩

움직이는 물체를 탭만 해도 중간 좌표에 멈추지 않도록, 입력 전 상태에 따라 목표로 복귀시킨다.

오래된 속도

마지막 이동 뒤 시간이 지나면 getter 단계에서도 샘플을 잘라 과거 속도를 버린다.

F-03

숨겨진 탭

requestAnimationFrame이 멈추면 visibilitychange에서 목표 상태로 종료한다.

F-04

감각 접근성

Reduced Motion에서는 직접 추적은 유지하되 관성·탄성만 제거하고, 키보드 경로를 병행한다.

06 / Critique

자기 비평

What remains unresolved

잘된 판단과
아직 검증하지 못한 것을 함께 남긴다.

Strongest decision

목표와 의도를 분리한 것

재그랩 뒤 목표 좌표만으로 닫힘 여부를 판단하면 이미 철회된 사용자의 의도가 되살아납니다. closingIntent를 독립 상태로 둔 것이 이 작업에서 가장 중요한 결정입니다.

Unresolved

실험실 밖의 입력

속도 추정은 짧은 이력 평균에 머물고, 고주사율 기기·멀티터치·보조기술 사용자와의 실제 사용성 검증은 아직 하지 못했습니다.

Future study

더 많은 감각 채널

coalesced pointer events, 멀티터치 충돌, 소리와 햅틱이 가능한 환경의 피드백을 다음 검증 항목으로 남깁니다. 아직 구현한 기능이 아닙니다.
